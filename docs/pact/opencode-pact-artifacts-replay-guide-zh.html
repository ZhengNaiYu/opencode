OpenCode PACT 可观测文件与 Replay 指南

生成日期：2026-06-24。示例 case：CPython_PEP-680_tomllib-Support-for-Parsing-TOML-in-the-Standard-Library_PR-31498。

核心结论：人工审计时应把 pact-artifacts/loops/<loop-id>/ 顶层目录视为唯一权威归档。.round-history/artifacts 当前只是调试用镜像，可能滞后于 finalize/complete 阶段，后续应默认关闭。

一、目录角色

位置 角色 人工检查建议
pact-artifacts/loops/<loop-id>/ PACT loop 的主归档目录，保存 plan、round prompt、patch、review、trajectory、snapshot、result、replay case。 权威入口 从这里看所有文件。
.round-history/artifacts 内部 git repo 里的 artifact 镜像，用于观察部分 artifact 随 round 演化。 当前不应作为权威来源；它可能缺少 finalize/complete/后续 round 文件。
case 根目录的 solution.patch LoLBench 最终提交给 evaluator 的实现 patch。 用于 benchmark 结果判断；可和 round-XX-eval.patch 做语义对比。
eval_orig/ LoLBench evaluator 输出，例如 run.log、agent_report.json。 用于判断最终 build/test 是否通过，不属于 PACT loop 内部决策链。

二、文件清单与用途

Loop 级文件

文件 用途 Replay 作用
loop-manifest.json 记录 loop id、project root、base commit、max rounds、planner/reviewer/worker backend 和 model。 确定 replay 的 base commit 和模型配置。
state.json 当前 loop 的 latest 状态，例如 running、complete、当前 round、phase。 只作为 latest pointer；round 级 replay 应优先看 round-XX-state.json。
source-plan.md 原始 LoLBench prompt 或用户输入需求。 追溯 canonical plan 的来源。
plan.md Round00 生成的 canonical plan，包含 goal、AC、tests、path boundaries、dependencies、task breakdown。 worker/reviewer 的权威目标输入。
todo.md 从 plan task breakdown 派生的执行任务表。 replay 时重建当轮 task context。
goal-tracker.md Humanize-style goal tracker，含 immutable goal/AC 和 mutable progress ledger。 判断 worker 是否偏离 AC，以及 reviewer 是否批准 ledger 更新。
replay-case.json latest replay case 拷贝。 只是便利入口；建议按 round 使用 round-XX-replay-case.json。
complete-state.md、finalize-summary.md finalize/complete 阶段的最终说明和校验摘要。 解释为什么 loop 结束，以及最终交付物做了哪些整理。

Round00 文件

文件 用途
round-00-plan-prompt.md 发给 planner 的 prompt。
round-00-plan-output.md planner 原始输出。
round-00-state.json、round-00-result.json 初始化阶段状态和结果。Round00 不消耗 implementation round 次数。
round-00-git-snapshot.json base commit 和初始 clean/dirty 状态。

每个 implementation round 的文件

文件 记录内容 主要用途
round-XX-prompt.md 本轮 worker 的完整自包含 prompt。 重跑 worker 的直接输入。
round-XX-context.json 本轮输入指针和 hash：plan、todo、goal tracker、feedback、worker/reviewer/planner model。 校验 replay 输入是否一致。
round-XX-state.json 本轮状态、phase、session id lineage。 审计 round 生命周期。
round-XX-pre-snapshot.json worker 开始前的 git HEAD、status、changed/untracked files、cumulative patch metadata。 定义本轮 replay 起点。
round-XX-post-snapshot.json worker 结束后捕获 patch/review 前后的 git 状态。 定义本轮输出状态；常与下一轮 pre snapshot 相同。
round-XX-events.jsonl 结构化事件流：round_started、tool_before/after、patch_captured、review_started/finished、round_finished。 做 timeline、失败定位、event-level replay。
round-XX-trajectory.json 脱敏后的 trajectory bundle，包含可获得的 driver/stdout/stderr/events 摘要。 复盘 worker 过程，比 events 更适合重建执行叙事。
round-XX-summary.md worker 自述本轮做了什么、是否需要 goal tracker 更新。 reviewer 的核心输入之一。
round-XX-workspace.patch workspace 累计 patch，保留测试文件等可观测变更，但排除 PACT 自身文件和 benchmark scaffold。 分析 worker 全部改动，包括测试草稿。
round-XX-eval.patch 用于 benchmark/eval 的累计实现 patch，排除 .pact/**、root patch 文件、以及 test.patch 声明的测试路径。 最终可提交 patch 的 PACT 版本。
round-XX-patch-artifact.json workspace/eval patch 的 sha、bytes、lines、changed files、excluded scaffolding metadata、apply check。 机器检查 patch 是否为空、是否污染、是否可应用。
round-XX-review-prompt.md 发给 reviewer 的 prompt。 复盘 reviewer 判断依据。
round-XX-review.md reviewer 原始 markdown 输出，要求包含固定结构和末尾 marker。 人工判断 reviewer 是否过严/过松。
round-XX-review-decision.json 解析后的 reviewer marker、parse status、backend/model、terminal line、feedback path。 程序化判断继续、进入 finalize、失败或停止。
round-XX-feedback.md 给下一轮 worker 的精简反馈。 下一轮 continuation prompt 的关键输入。
round-XX-result.json 本轮状态、failure category、metrics、artifact path map。 汇总本轮 outcome，适合批量统计。
round-XX-evidence.json 机器可读 evidence manifest，列出关键文件是否存在和 sha256。 完整性校验、批处理索引。
round-XX-evidence.md 同一 evidence 的人工可读表格。 人工审计时快速扫文件链。
round-XX-replay-case.json 本轮 replay package，包含输入文本、artifact map、snapshot、trajectory、review、baseline result。 round 级 replay 的主入口。

三、Replay 怎么做

结果级 replay

目标是验证归档 patch 能否在 base commit 上复现最终文件状态。

  1. 从 loop-manifest.json 读取 base_commit。
  2. 准备同一仓库的干净 checkout，并切到 base commit。
  3. 应用 round-XX-eval.patch 或最终 solution.patch。
  4. 重新捕获规范化 patch，并比较 changed files、文件内容 hash、recaptured patch hash。

Round 级 replay

目标是复现某一轮 worker 输入到输出的过程。

  1. 选择 round-XX-replay-case.json。
  2. 用 base commit 加上一轮累计 eval patch 还原本轮 pre state。
  3. 用 round-XX-prompt.md、round-XX-context.json、feedback 和 plan/todo/goal tracker 作为 worker 输入。
  4. worker 执行后捕获 patch，并和 round-XX-eval.patch 或 expected delta 做语义对比。

当前限制：代码里已有 replay case export，但还没有独立 replay runner。现在能稳定做的是 patch-level replay；真正“重新调用 worker 并比较输出”的 runner 仍需要后续实现。

五、人工审计建议

  1. 先看 loop-manifest.json、state.json、finalize-summary.md，确认 loop 的最终状态和模型配置。
  2. 再按 round 查看 round-XX-prompt.md、round-XX-summary.md、round-XX-review.md、round-XX-feedback.md。
  3. 如果怀疑 patch 污染，看 round-XX-patch-artifact.json 的 excluded_scaffolding_files 和 excluded_test_patch_files。
  4. 如果怀疑上下文漂移，看 round-XX-context.json 和 pre/post snapshot 的 hash。
  5. 如果怀疑 worker 做了不该做的操作，看 round-XX-events.jsonl 和 round-XX-trajectory.json。
  6. 如果要做结果复现，用 round-XX-eval.patch 在 base commit 上应用并重新捕获 patch。

六、后续设计记录

已在 implementation plan 里记录新的 follow-up：默认关闭 .round-history，把顶层 loop 目录作为唯一权威归档。为了保留历史语义，后续应补充必要的 round-scoped ledger snapshot，例如 round-XX-goal-tracker-pre.md 和 round-XX-goal-tracker-post.md。

一句话版本：PACT replay 的权威链路应该是 base commit + round package + patch/evidence/result，而不是依赖临时 worktree 路径或内部镜像目录。
