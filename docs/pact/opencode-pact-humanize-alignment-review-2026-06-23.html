一、结论

基本对齐

约 70-75% 对齐 Humanize/RLCR 的控制模型。

这里评估的是机制对齐，不是 worker 解题质量。

当前 OpenCode PACT 已经具备 Humanize/RLCR 的主干：强结构 plan/todo/goal tracker、受保护 ledger、 reviewer gate、多轮 continuation、implementation -> review -> finalize phase、patch/review/result/replay artifact chain。

主要差距集中在 Humanize 更强的运行时控制与审计细节：没有 Claude Code Stop Hook 等价的硬阻塞、 没有原始 worker trajectory artifact、没有 Codex usage 账本、没有 evidence bundle 和 per-round history repo commit， goal tracker 更新也还比较轻量。

上一轮 smoke 的机制结论： PACT loop 确实推进了 4 个完整 review-gated round，并进入第 5 轮 finalize prompt。 LoLBench 外层 1500s timeout 截断了 finalize round，所以最终 loop 被标记为 status=stopped、 phase=stopped、failure_category=agent_timeout。 这说明 loop 机制可跑通，但 finalize 还需要更好的外层超时预算或更短 finalize prompt。

三、当前具体流程

1. Loop Start输入 plan、max rounds、planner/reviewer/worker 配置；创建 loop manifest、state、plan/todo/goal tracker。
2. Worker RoundOpenCode worker 读 round prompt，修改代码，写 summary；plugin 记录 tool events。
3. Patch Captureidle 时捕获 workspace/eval patch，排除 PACT 与 benchmark scaffolding。
4. Reviewer GateCodex reviewer 读 summary、eval patch、metadata，输出 review；只认 final PACT_COMPLETE。
5. Continue/Phasecontinue 生成下一轮 prompt；complete 进入 review/finalize；finalize summary 后 complete。

1. LoLBench/OpenCode smoke 启动

输入处理输出
LoLBench PROMPT.md、目标 repo workspace、worker model、PACT plugin config。 smoke 路径使用 pact-run-driver.ts 多次调用 opencode run。 第一次 prompt 要求调用 pact-start-loop，后续如果 state 仍 running，则用 -s active_session_id 回到同一个 session，并把 round-XX-prompt.md 作为输入。 OpenCode session、PACT loop、agent log、LoLBench run dir。

2. pact-start-loop 初始化

输入核心行为落盘文件后续作用
plan_file、max_rounds、full_alignment_interval、 planner/reviewer/worker backend 与 model。 拷贝原始 plan；Codex planner 默认 gpt-5.5 生成/规范化 todo 和 goal tracker； 初始化 state；把 .pact/ 幂等加入 workspace 的 .git/info/exclude。 loop-manifest.json、state.json、plan.md、 todo.md、goal-tracker.md、round-01-prompt.md、 round-01-state.json、round-01-context.json、round-01-events.jsonl。 形成可复盘的 loop identity、模型配置、目标快照、任务账本和第一轮 worker prompt。

3. Worker 执行与 tool/session events

输入核心行为落盘文件后续作用
round-XX-prompt.md、todo.md、goal-tracker.md、上一轮 feedback.md。 worker 修改代码并写 round-XX-summary.md。 plugin 对 tool before/after 记录轻量摘要；只拦截写操作保护 ledger； benchmarkStrictNetwork 可拦截明显访问 GitHub/python.org/PyPI 等 benchmark source 的工具调用。 round-XX-summary.md、round-XX-events.jsonl，以及 workspace 里的业务代码改动。 summary 是 reviewer gate 的主输入；events 用于观测工具调用密度和被拦截行为。

4. Patch Capture

输入核心行为落盘文件后续作用
当前 git workspace、root solution.patch、root test.patch。 捕获 workspace.patch 和 eval.patch。 两者都排除 .pact/**、root solution.patch、root test.patch； eval.patch 还排除 root test.patch 内声明的测试文件。 round-XX-workspace.patch、round-XX-eval.patch、 round-XX-patch-artifact.json。 reviewer 只看 eval patch；workspace patch 保留更完整可观测性。 patch artifact 记录 changed files、sha、bytes、lines、apply check、被排除 scaffolding/test 文件元数据。

5. Reviewer Gate

输入核心行为落盘文件后续作用
plan、todo、goal tracker、round summary、eval patch、patch metadata。 默认同步调用 codex exec --ignore-user-config --skip-git-repo-check -m gpt-5.4-mini -c model_reasoning_effort="medium" -C <projectRoot> -。 reviewer 输出固定短结构。只有最后一个非空行是 PACT_COMPLETE 才算 complete； PACT_STOP、PACT_CONTINUE 和缺 marker 都视为 continue。 round-XX-review-prompt.md、round-XX-review.md、 round-XX-feedback.md、round-XX-review-decision.json。 形成机器可读 gate 结果；continue feedback 会进入下一轮 prompt； complete 会触发 phase transition。

6. Phase Transition 与收口

当前 phasereviewer marker下一步落盘文件
implementation continue 当前 round + 1，生成 continuation prompt。 round-(XX+1)-prompt.md、state/context/events。
implementation 或 full_alignment PACT_COMPLETE 进入 review phase，而不是直接 complete。 round-XX-feedback.md 写 review phase 指令；下一轮 prompt 为 code-review checkpoint。
review PACT_COMPLETE 进入 finalize phase。 round-XX-feedback.md 写 finalize 指令；下一轮 prompt 要求写 finalize-summary.md。
finalize 不再跑 reviewer；等待 summary 发现 finalize-summary.md 后写 complete state。 complete-state.md、最终 round-XX-result.json。

四、可观测文件清单

文件内容后续用途
loop-manifest.jsonloop id、project root、plan sha、max rounds、phase config、planner/reviewer/worker backend/model、base commit。全局 provenance；判断本轮跑法和模型配置。
state.json当前 status、phase、round、active session、last review/feedback、goal tracker immutable hash。driver 续跑和事件 hook 判断下一步。
plan.md原始需求/计划快照。replay、review、goal tracker 来源。
todo.md从 plan 派生的 task ledger，包含 task id、target AC、tag、依赖、状态。worker 每轮选择下一步任务。
goal-tracker.mdHumanize-like immutable/mutable section：Ultimate Goal、AC、active/completed/deferred/open issues/evolution。长周期记忆和任务状态锚点。
round-XX-prompt.md本轮 worker prompt；包含初始任务、continuation、review phase 或 finalize phase 指令。driver re-enter session 的输入；replay 输入。
round-XX-context.jsonsession id、worker/reviewer/planner 元数据、prompt/todo/goal tracker/feedback 路径与 hash。重放和审计每轮输入上下文。
round-XX-state.jsonround 级 phase/status 快照。定位 round 在何处开始/结束/失败。
round-XX-events.jsonlround_started、tool_before/after、patch_captured、review_started/finished、round_finished、replay_exported 等摘要事件。轻量 trajectory；统计 tool event count；排查 blocked network 或缺 summary。
round-XX-summary.mdworker 自述：做了什么、验证了什么、遗留什么、是否请求 goal tracker 更新。reviewer 主输入；下一轮 context。
round-XX-workspace.patch完整 workspace diff，排除 PACT 和 root scaffolding。可观测完整改动，包含测试文件。
round-XX-eval.patchbenchmark 提交 patch，排除测试 patch 声明文件。reviewer 和 LoLBench 最终评价的业务 patch。
round-XX-patch-artifact.jsonworkspace/eval patch metadata、changed files、sha、bytes、lines、apply check、excluded scaffolding/test files。patch pollution 排查、LoLBench artifact coverage、replay。
round-XX-review-prompt.md实际发给 Codex reviewer 的 prompt。reviewer 调用可复盘；便于 prompt 迭代。
round-XX-review.mdreviewer markdown 输出，固定短结构。人类阅读和 feedback 来源。
round-XX-feedback.md给 worker 下一轮读取的反馈，complete 时写 phase transition 指令。continuation/review/finalize prompt 的输入。
round-XX-review-decision.jsonmarker、parse_status、terminal_line、backend/model、resulting status/phase。机器可读 gate 结果。
round-XX-result.jsonstatus、loop_phase、failure_category、模型元数据、metrics、artifact paths。结果聚合、失败分类、LoLBench 产物审计。
replay-case.json最近一次成功导出的 replay case，包含 plan/prompt/context/patch/review/result 摘要。checkpoint replay 和未来 A/B。当前是 loop-level latest，会被后续 round 覆盖。
complete-state.md / stop-state.mdcomplete 或 stopped 的人类可读终态说明。快速判断 loop 如何收口。

五、与 Humanize/RLCR 的对齐矩阵

Humanize/RLCR 机制OpenCode PACT 当前状态对齐度说明
强约束 plan contract Codex planner + deterministic fallback 会生成 AC/task ledger。 部分对齐 Humanize 的 gen-plan schema 更完整：positive/negative tests、path boundaries、pending decisions 等更强。LoLBench 原始 prompt 通常不是完整 Humanize plan。
plan -> goal tracker 投影 loop start 生成 todo.md 和 goal-tracker.md，含 immutable/mutable section。 基本对齐 OpenCode 用 planner/fallback 在 round 1 前完成投影；Humanize 更像 Round 0 agent 初始化。
受保护 goal tracker 写工具保护 ledger 文件，并用 immutable hash 检查 goal tracker immutable section。 基本对齐 当前只拦写，不拦读，已避免 worker 读不到 feedback 的问题。
reviewer gate 默认同步 Codex CLI reviewer，固定 prompt 输出结构，review 失败/timeout 有 artifact。 基本对齐 上一轮 smoke 证明 reviewer 可连续 gate 4 轮。
二态 reviewer protocol 仅 final PACT_COMPLETE 完成；其他均 continue。 对齐 兼容 deprecated PACT_STOP，不再把它当终止信号。
Stop Hook 硬门禁 OpenCode 没有等价 Stop Hook；使用 session.idle 近似。 未完全对齐 这是机制能力差异。worker 退出后由 idle hook 继续推动，不是像 Claude Code Stop Hook 那样硬阻止退出。
多轮 continuation pact-run-driver 读取 state 和 round-XX-prompt.md，复用 active session。 基本对齐 上一轮 smoke 的 round 1 -> 4 证明可工作。
full alignment checkpoint 代码已实现 interval 触发和 prompt，但上一轮 smoke 未实际触发。 部分对齐 因为 implementation 在 round 3 已 complete，round 5 已是 finalize，所以 full_alignment_interval=5 未覆盖真实 round。
review phase implementation complete 后进入 review phase，round 04 执行 code-review checkpoint。 对齐 smoke 中 round-03-review-decision.json 明确 resulting_phase=review。
finalize phase review complete 后进入 finalize phase，生成 round 05 finalize prompt。 部分对齐 机制已到位，但上一轮被外层 timeout 截断，没有 finalize-summary.md 和 complete-state.md。
每轮 trajectory 有 round-XX-events.jsonl 和 LoLBench agent.log，但没有 Humanize-style raw worker trajectory artifact。 部分对齐 Humanize 每轮保存 trajectory.json、metadata、git snapshot、evidence bundle，OpenCode 目前是摘要级。
Codex usage/token 账本 暂未记录 planner/reviewer usage。 未对齐 Humanize 记录 codex usage log 和 summary；OpenCode 可以后续从 Codex JSON output 或 CLI telemetry 补。
artifact/replay 有完整 JSON/patch/review/result/replay chain。 基本对齐 OpenCode 在 replay 方面比最初 Humanize-like 控制更结构化；但 replay-case.json 是 latest 覆盖，不是 per-round archive。
patch 边界与 benchmark scaffolding 排除 .pact/**、root solution.patch、root test.patch，并记录被排除元数据。 对齐且适配 LoLBench 上一轮最终 solution.patch 未污染 PACT artifacts。

六、当前缺口与建议

优先级缺口建议预期收益
P0 finalize phase 被外层 timeout 截断，导致机制未完整展示 complete 收口。 给 finalize round 更短 prompt/更小任务边界，或在 driver/LoLBench 层给进入 finalize 后的最后一次 invocation 单独预算；smoke 可用更小 case 或更短 max rounds 验证 complete path。 证明完整 implementation -> review -> finalize -> complete 链路。
P1 full alignment 已实现但上一轮未触发。 增加一个 full_alignment_interval=2 的 smoke，或加显式 force-full-alignment 测试入口。 验证 Humanize 的“周期性全局对齐”机制真实可用。
P1 没有 Humanize-style raw trajectory、usage、evidence bundle、history repo commit。 增加 round-XX-trajectory.json 或至少保存 OpenCode session export；记录 planner/reviewer Codex usage；生成 round-XX-evidence.md/json；可选维护 .round-history。 可观测性从“摘要级”提升到“复盘级”。
P1 continue round 的 failure_category 当前是 unknown。 将正常继续分类成 needs_continuation 或令 failure 为 null，并增加 review_outcome=continue。 结果聚合更干净，避免把正常 reviewer feedback 误读为异常。
P2 goal tracker 更新还偏轻量，主要 append reviewer-approved note。 把 Goal Tracker Update Request 解析成结构化表格操作：active -> completed/deferred/open issue/evolution。 更接近 Humanize 把 tracker 当 durable state machine 的设计。
P2 lolbench-smoke.ts 目前更像配置 helper，尚未完全接成通用 smoke CLI。 把 ZAI env loading、provider config merge、preflight、driver invocation 整合成一个明确 smoke command builder。 减少手工拼命令时出错，提高 smoke 可重复性。
P2 Stop Hook 无法完全复刻。 继续把它标成非目标；若 OpenCode 后续有阻塞式 stop/session lifecycle hook，再替换 idle gate。 避免为了追求 100% 复刻而过度设计。

七、最终判断

如果把 Humanize/RLCR 的核心定义为 plan -> tracker -> reviewer-gated rounds -> continuation -> review/finalize -> durable artifacts， 当前 OpenCode PACT 已经基本对齐。

如果把 Humanize/RLCR 的完整产品形态定义为 强 plan schema + Round 0 投影 + Stop Hook 硬门禁 + raw trajectory + usage accounting + evidence/history repo， 当前 OpenCode PACT 还只是一个实用化的 v1 复刻：主控制流跑通了，可观测文件链也足够做 LoLBench artifact coverage 和 replay 起步， 但还缺 Humanize 那种“每轮全量审计包”的厚度。

建议验收口径： 当前版本可以称为 Humanize-inspired PACT v1，不宜称为完整 Humanize clone。 下一步最有价值的不是继续加 phase，而是补齐 finalize smoke、full alignment smoke、trajectory/usage/evidence 三类审计物。
